# 日志中心（板端 MCAP）

入口：工具 → 日志中心。选择“仿真机日志”，点击“刷新仿真机”，展开日期目录。
选择文件后点击“PlotJuggler 查看”或双击文件，日志中心会下载仿真机 MCAP，
并在独立的 PlotJuggler 窗口中打开。也可只下载文件。点击“打开本地 MCAP”
会通过系统文件选择器选择文件并直接打开 PlotJuggler；下载过的文件会出现在
本次打开日志中心的“本地日志”列表。曲线选择、缩放、FFT 和 CSV 导出在
PlotJuggler 中完成。完整 MCAP 文件直接从磁盘加载，不再经过 WebView 的
64 MiB 自动打开限制。
选中“仿真机日志”文件后，日志中心会让任务机直接读取 MCAP 记录并返回
Profile、Library、压缩方式、通道、仿真时间范围与记录时长。新固件保存的日志
还包含标准 MCAP Summary/Statistics，因此可显示消息总数和各通道消息数，
并用各通道消息数除以整段日志的仿真时长显示平均频率。间歇发送的通道会把
未发送时段计入平均值；时间跨度无效或没有通道消息数时显示“—”。
这一步只传输简短信息，不下载完整 MCAP。文件列表刷新时不逐个解析文件。
旧固件生成的日志没有 Statistics，任务机可跳过压缩数据读取 Chunk 时间范围，
消息数显示“未提供”。精确统计旧日志的消息数需要扫描并解压全部 Chunk。
这里的 MCAP 时间戳是 **JSBSim 仿真时间**，文件日期才是任务机时钟时间。
轻量读取不会解压或校验所有 Chunk；显示摘要不代表整个文件已通过完整性校验。
旧固件没有信息命令时，日志中心会保留原有文件信息与下载/查看操作，
并显示信息读取失败原因。
下载过程中会显示已接收大小和进度；网络长时间没有数据时会重新下载一次，
自动通信模式还会尝试另一条 USB 或网络文件通道。仍无法完成时会报出具体错误。
点“PlotJuggler 查看”时，USB 和网络下载前会检查板端文件头，打开前还会校验
完整的 MCAP 消息和压缩数据；损坏的日志会在日志中心显示错误。点“下载”时
会保存传输完整的原始文件，即使它已经损坏，并明确提示它不能用于绘图。
完整且大小匹配的本机副本会直接复用，再次查看无需重复下载。PlotJuggler
会在文件下载完成后启动；未完成的 `.part` 文件不会被当成日志打开。

新固件的 MCAP 同时保存两类曲线：`/jsbsim/fdm_state` 中的固定状态和已选属性
按“MCAP 记录频率”采样；实时数值属性树、CPU/RAM 与任务遥测按原有实时包的
频率保存，并在 PlotJuggler 中显示为与实时窗口相同的属性路径。记录频率只控制
前一类曲线的点数。升级前生成的 MCAP 不会补出当时未记录的属性。

板端已完成的日志位于 `/mnt/sdcard/LOG/YYYY-MM-DD/`，以 `.mcap` 结尾。
仿真运行时日志只在任务机 RAM 缓冲区中；STOP 时才创建 `.active` 临时文件并写入 SD，
成功保存后重命名为 `.mcap`。日志中心只列出 `.mcap`，所以正在运行的段和保存失败
保留的 `.active` 不会显示。缓冲区满时保留前段记录，后续样本会丢弃。
每次 START 会创建新段。日期来自板端时钟；上位机启动仿真前会尝试同步该时钟。

如果仿真结束后列表没有新文件：

1. 在日志中心点击“刷新仿真机”，查看是否有读取失败提示，并检查其他日期目录。
2. 确认板端 SD 卡已挂载、`/mnt/sdcard/LOG` 可写，且该模型运行配置启用了 MCAP。
3. STOP 后在板端检查 `LOG` 日期目录内是否只有 `.active`；同时查看串口输出中的
   `JSBSim MCAP: cannot create`、`cannot start logger`、`save failed`、`saved` 和
   `finalized on simulation stop`。已创建文件后的保存失败会保留 `.active` 与错误路径；
   如果创建文件就失败，任务机不会留下 `.active`。
4. 若板端存在 `.mcap` 而列表仍为空，检查上位机“本地设置 → 仿真机通信”的
   USB/网络模式及连接状态。文件传输在自动模式下按 USB 协议探测结果选用 USB
   或网络；参见 [USB Bulk 说明](usb-bulk.md)。

“工具 → 遥测记录”是独立的**本机 JSONL**记录功能，保存上位机收到的报文，
不会创建板端 MCAP，也不会填充日志中心的“仿真机日志”列表。
参见 [本机遥测记录](TELEMETRY_RECORDING.md)。
