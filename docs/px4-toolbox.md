# PX4 工具箱

从「工具 → PX4 工具箱 · 参数 / 日志 / 打印 / NSH / 仿真测试 / 软件飞控」打开。工具箱自动接收**仿真机已有的 MAVLink 转发数据**，没有独立连接按钮，也不在电脑上另开飞控 USB 串口。

桌面端使用系统独立窗口，主界面没有遮罩，可继续编辑模型或观察视景。使用工具箱标题栏移动窗口、拖动窗口边缘缩放，也可移到另一台显示器；位置、大小和最大化状态保存在本机。显示器移除后，下次打开会回到可见区域。关闭工具箱只隐藏窗口，保留连接、脚本和后台测试；再次打开复用原窗口。关闭主程序会退出整个应用并清理后台测试。

工具箱窗口是唯一的工具连接拥有者。主界面视景和 MCP 通过跨窗口消息调用同一个测试入口，状态同步不会创建第二条飞控连接。控制请求不自动重试，未及时处理的启动请求会过期。

## 数据入口

- 默认自动监听仿真机**开机常驻转发服务的 UDP 14553**，没有加载模型也可读取飞控。切换模型或实例不会重建该通道，参数和 NSH 会话保持。
- 转发模块已从画布和部件库移除；旧缓存和导入 XML 不再生成转发节点，保存模型时移除旧的 `MAVLINK_FORWARD` 输入。
- PX4 目标 SYS/COMP 从心跳识别；取得仿真机地址时只接受该主机的数据。识别后固定 UDP 回传来源，其他发送端不能改变参数、日志或终端指令的回传目标。
- 当前入口使用网络转发。UDP 端口被其他程序占用时会显示明确错误；QGC 和工具箱分别使用不同端口。
- 飞控与仿真机之间既可使用 USB，也可使用主实例的 UDP HIL 通道。转发服务自动跟随当前 HIL 来源，USB 回传使用共享串口队列，UDP 回传由原 HIL 接收任务通过同一套接字发送；不会另开竞争的 HIL 监听端口。旧固件仅转发 USB，需要更新仿真机固件才能支持 UDP HIL。

### 与 QGC 同时使用

仿真机独立 `mavlink_router` 任务共享现有 USB 读取线程，向电脑发送两路完整报文：
QGC 使用 UDP 14550，工具箱使用 UDP 14553，两路均支持指令回传。
关闭编辑器不影响 QGC，单个客户端退出也不影响另一客户端。
QGC 普通 UDP 连接不要勾选“高延迟链路”。

板端持久配置位于 `/mnt/home/mavlink-router.conf`，与模型 XML 无关：

```ini
device=/dev/ttyACM0
baud=921600
host=192.168.3.109
qgc_port=14550
toolbox_port=14553
```

在工具箱的 **转发设置** 页读取和管理板端服务：

- 显示独立服务状态、仿真机地址，以及 QGC/工具箱两路累计收发字节和错误。
- 修改 USB 设备、波特率、目标电脑 IPv4、QGC UDP 端口和工具箱 UDP 端口。
- “保存并应用”在同一仿真机执行保存前比较、暂存回读、替换及最终回读；运行中的服务重新启动，停止的服务保持停止。工具箱自动采用实际运行端口。
- 配置变化或目标仿真机变化会拒绝过期保存；应用失败会尝试恢复旧配置、重新启动并核对实际运行配置。
- “停止服务”只停止本次运行的转发，仿真机重启仍会自动启动。未保存修改时须先保存或放弃修改，再启停服务。

转发设置不再写入模型 XML，无需重载模型。板端仍可通过 `jsbsim router status`、
`jsbsim router stop`、`jsbsim router start` 管理。服务关闭继承的管理会话句柄，
停止转发后保留任务组，避免中断仍被 HIL 使用的共享 USB 线程。

## 进入 / 退出仿真

工具箱顶部在所有页签只显示一个切换按钮，根据飞控心跳中的实际 HIL 状态互斥显示：正常模式显示 **进入仿真**，HIL 模式显示 **退出仿真**。尚未识别状态时显示 **等待飞控状态**，执行过程中显示 **正在切换…**。复用现有飞控连接，无需先读取完整参数列表。

旁边的 **重启飞控** 独立发送 `MAV_CMD_PREFLIGHT_REBOOT_SHUTDOWN`（param1=1），不写入参数、不改变仿真配置或 GPS 备份。仅在连接在线、双向链路可用、未解锁且没有其他飞控操作时可执行。点击后显示 **正在重启…**，等待重新连接并核对同一硬件身份；回执丢失时不重复发送。拒绝、重连超时会显示错误。重启和仿真切换互斥，重启期间其他飞控操作暂不可用。

- **进入仿真**：读取硬件 UID 和当前配置，保存原始 `GPS_1_CONFIG`，将 `SYS_HITL` 写为 `1` 并独立回读，经 MAVLink NSH 执行同步 `param save`。确认保存成功后发送 `MAV_CMD_PREFLIGHT_REBOOT_SHUTDOWN`（param1=1）。
- **退出仿真**：将 `SYS_HITL` 写为 `0`，恢复同一飞控的原始 GPS 端口，保存并重启。备份按硬件 UID 保存在本机，关闭并重新打开工具箱后仍可恢复。GPS 端口如果已被另行改成其他非零值，则保留该手动配置。
- 心跳中显示的是飞控当前 HIL 状态。按钮仅在双向链路在线、模式和解锁状态已确认且飞控未解锁时可用；不可用的具体原因会在旁边显示。写参数、保存和重启前也会重新检查。切换过程中禁止并行写参数、下载日志、操作转发或输入 NSH。开发环境热更新时，旧版连接对象会自动重建，避免缺少状态字段后一直禁用。
- 自动等待最多 90 秒，结合连接重建、心跳间隔、启动计时回退或 HIL 状态变化检查重启，再重新核对硬件 UID、`SYS_HITL`、HIL 状态和已恢复的 GPS 配置。重启回执丢失时继续检查，不重复发送重启命令。
- 写入或保存失败不发送重启指令；重启拒绝、模式不符和重连超时分别显示错误。已经写入的参数可能仍然有效，GPS 备份保留供重试。若原本已处于目标模式且没有待恢复配置，不再重复重启。

GPS 备份用于处理当前 PX4 启动脚本在 HIL 下把 `GPS_1_CONFIG` 设为 `0` 的行为。从其他工具进入仿真、换电脑或清除应用数据后可能没有备份，此时退出仅关闭 HIL 并明确提示 GPS 配置保持当前值，不猜测原始端口。

此按钮切换 PX4 的启动模式，不更换机型、控制器或仿真模型。固件需要包含 `pwm_out_sim` 等 HIL 所需模块；切换成功表示重启后的 HIL 状态和配置一致，仿真传感器与执行器闭环仍取决于模型及链路配置。

`/home/qikai820/src/PX4-Autopilot/build/px4_sitl_default`。支持手动输入、系统文件夹选择和重新检测；

`etc/init.d-posix/airframes` 读取机型编号、模型名及说明。目录不完整时保留检测结果并禁用启动。

可选择实例 0～9、仿真倍率 0.1～10、起始经纬度及海拔。UDP 地址留空使用本机 `127.0.0.1`。
启用电脑端模型服务时，空地址自动采用本次生效的本机 HIL 配置；否则采用已经发现的仿真机，
未发现仿真机时填入本机地址及 14561/14560 端口。已填写的地址保持不变，也可点击“使用本机模型连接”。
允许手动修改；PX4 和模型端口分别配置，同机运行不得相同，实例编号不会自动修改这两个端口。
起始位置通过 `PX4_HOME_*` 传递，外部模型传感器数据决定实际位置。
飞控机型配置控制器和电机布局，JSBSim 模型（例如 `F450_PX4`）仍在仿真机中选择。

页面显示实际参数构成的启动命令、环境变量、独立工作目录，以及最近 1500 条标准输出/错误输出。
运行状态每秒刷新，按钮在启动和停止之间切换。打开页面后先检测已有 PX4，按实际进程、
构建路径/实例或 HIL 套接字所有者识别；已有运行实例时不重复启动，并恢复可读取的运行配置。
其他入口启动的 PX4 会明确标示，历史 stdout/stderr 不可读取；可手动停止，退出上位机时保留它。
单纯的端口占用不会被视为 PX4 运行。本机模型服务的就绪状态也持续刷新。
启动前重新校验目录、机型和参数；UDP 监听端口占用时拒绝启动。运行后锁定配置，禁止重复启动，
显示 PID；进程退出后显示退出码并允许修改重启。“运行中”仅表示进程存活，传感器、估计器和
控制闭环须通过日志与飞控心跳验证。启动功能不更换工具箱现有的仿真机 MAVLink 转发数据入口；
SIH/TCP 的数据连接需另外配置。

软件飞控在应用数据目录下按构建路径、模式、机型和实例使用独立工作目录，保存自己的参数和日志。
不改写所选 PX4 构建目录。生成的 `launcher.rcS` 复用该构建的启动流程，UDP HIL 在传感器启动前
开启 `SYS_HITL` 和 MAVLink UDP，跳过外部仿真器启动；TCP/SIH 则关闭 `SYS_HITL` 并使用原有仿真入口。
不识别的 rcS 结构会明确拒绝启动。各 PX4 构建是否包含对应模块以及 UDP HIL 的实时调度支持仍需实机核对。

同一上位机一次管理一个软件飞控进程。关闭工具箱或切换页签后继续运行，重新打开恢复后台状态；
退出上位机时停止其拥有的进程及同组子进程，超时强制清理。配置保存在本机，下一次打开恢复。

## 参数

获取和修改 PX4 参数，支持完整列表、缺失索引重试、全局搜索、收藏、固件类别/分组、前缀分组及本机自定义分组。选中参数后，在详情区输入新值或选择枚举，点击“写入飞控”；使用默认值只填充输入框。写入采用 PARAM_SET，收到目标参数的 PARAM_VALUE 后，再通过 PARAM_REQUEST_READ 按名称独立回读；值一致才提示成功并更新列表。超时重试，拒绝、断开或回读不符会显示明确结果，未确认时须重新读取核实。此操作不会自动重启飞控。

整型按实际参数类型与飞控编码写入，浮点型按 FLOAT32 精度确认。输入须符合参数类型；匹配飞控的元数据还约束数值范围及只读属性，并提示重启要求。内置参考库的范围只供参考。`.params` 导出使用 QGC 的 SYS、COMP、名称、值、类型列格式，部分读取会在文件头标明。

分组与说明参考 QGC 的元数据机制：`category/group`、`shortDesc/longDesc`、默认值、范围、单位、枚举、位掩码及重启要求。优先读取飞控发布的 COMPONENT_METADATA / COMPONENT_INFORMATION 和参数元数据 URI，支持 MAVLink FTP、HTTP(S)、JSON/XZ 与本地 XML/JSON 导入。带 CRC32 的数据校验后按 URI/CRC 缓存，缺失时回退到内置 QGC/PX4 参考库。参考库或手动导入不会显示为已验证的固件匹配；自定义固件应发布对应元数据。

本机参数元数据缓存总量限制为 2 MiB，自动发现的属性路径缓存另限 1 MiB，均按 UTF-16 文本大小估算。启动时也会整理旧版本留下的超额缓存；只清理可重新读取的元数据和属性路径，不清理工程、XML 基线、脚本或用户设置。缓存写入失败时继续使用内存中的数据，仿真配置页和属性浏览器保持可用；版本快照保存失败会明确提示，PlotJuggler 频率已应用但偏好未保存时也分别显示结果。

缺少元数据的参数按前缀归类，并显示“暂无元数据说明”。参数值按 PX4 字节编码解析整型/浮点型，不把整型参数的 float 容器直接当作数值。

## 日志

通过 MAVLink LOG 协议读取板载列表并下载，可选择多个日志依次保存、查看进度和取消。按块追踪覆盖范围，重试缺块，校验 ULog 后才将隐藏的 `.part` 文件替换为目标 `.ulg` 文件；取消或失败不会覆盖原文件。

支持打开本地 `.ulg`，查看时长、主题/实例、采样数量与频率、参数记录、固件信息以及 dropout。当前支持 ULog v1、单个文件最多 512 MiB；本地截断文件会明确标示，下载的截断文件不作为完整日志保存。

## 仿真测试

测试页的 **视景观察** 可进入飞行视景的简洁浮层；点“详情”展开反馈与事件，点“隐藏”收起。隐藏浮层、关闭工具箱或切换工作区后测试继续运行，视景底部保留状态、时间和 **终止**。工具箱与视景复用同一次测试和连接，运行期间观察其他实例不会改变测试绑定。见 [视景中的测试操作](FLIGHT_TEST_WORKBENCH.md#在飞行视景中观察测试)。

紧凑 Blockly 风格积木支持飞控模式/解锁/起降、模拟遥控打杆、等待状态、条件、循环以及 2～4 路并行。不同轴可同时打杆，支持全部/任一汇合；同轴冲突或飞控状态指令重叠会明确失败。

“遥控输入”中的 **通道控制** 可保持或释放 RC1～RC18 / AUX1～AUX6，并提供 **普通旋翼 / 矢量旋翼** 快捷设置，自动使用飞控的 `RC_MAP_VECTOR_SW` 通道。通道值持续到后续改值、释放或退出。物理 RC 测试不限制 `COM_RC_IN_MODE` 的取值，执行前读取通道校准，不自动写参数。详见 [通道控制与旋翼模式开关](FLIGHT_TEST_WORKBENCH.md#通道控制与旋翼模式开关)。

积木保存为标准 JSBSim 事件 XML，可导入、直接编辑、离线预演及导出运行记录。实际执行复用当前转发 UDP 会话，由 Rust 后台默认按 50 Hz 发送完整 `RC_CHANNELS_OVERRIDE`，按现有主杆/AUX 映射和校准模拟遥控器，飞控指令要求 ACK 和实际状态双确认。运行前检查 HIL 与所选实例运行状态，不限制 `COM_RC_IN_MODE` 的取值；运行期间锁定冲突操作。

“遥控输入”中的 **油门控高** 可指定目标相对高度和持续时间，根据高度及升降速度反馈自动调整油门杆，模拟人工推杆、制动和保持；支持 ALTCTL、POSCTL 和 STABILIZED，可与其他独立轴并行。右侧显示控高反馈，“控高调节”中设置杆量限幅与变化速率，详见 [飞控仿真测试工作台](FLIGHT_TEST_WORKBENCH.md#油门控高)。

默认模板用于已悬停的仿真机，不自动解锁/起飞。此入口支持 `test/*` 飞控属性桥的 FGScript 事件子集；模型加载/动力学脚本仍使用原有仿真入口。完整操作、并行规则、XML 兼容范围与退出行为见 [飞控仿真测试工作台](FLIGHT_TEST_WORKBENCH.md)。

## PX4 打印

“PX4 打印”页持续显示当前飞控发出的 MAVLink `STATUSTEXT` 状态消息，包含本机接收时间、严重级别、SYS/COMP 与原始文字；警告和错误使用不同颜色。支持关键词搜索、级别筛选、自动滚动、暂停/继续显示、复制当前显示内容和清空。暂停只冻结显示，后台继续接收；向上滚动时自动停止跟随，可勾选“自动滚动”回到最新消息。

复用工具箱已有连接，无需打开 NSH，不发送额外飞控指令。切换页签或隐藏工具箱继续缓存，最多保留最近 2000 条；短暂断线重连保留历史，更换数据来源时清空，退出应用后不保留。长消息按分片拼接，缺片会明确标记。

此页显示通过 MAVLink 发布的飞控消息；NSH 命令的输出仍在“NSH 控制台”查看，未通过 MAVLink 发布的板端调试串口打印不会出现在此页。

## NSH

工具箱 NSH 经同一仿真机转发链路使用 MAVLink SERIAL_CONTROL Shell，进入页签后自动建立持续会话。键盘字节、Ctrl+C 和终端输出持续传输，ANSI 光标/清屏与长时间输出由共享的 xterm 终端处理；切换页签保留会话，退出工具箱释放会话。

原有「NuttX NSH 控制台」与工具箱共用终端组件。原入口在网络模式下自动使用仿真机 Telnet 地址（端口沿用 `NSH_TELNET_PORT`，默认 23）；USB 与自动模式的旧单条命令接口保留兼容路径，不将其伪装成持续会话。

Linux 桌面的 HTTP(S) 元数据下载使用 `curl`，失败时保留具体地址与服务器错误。XZ 元数据使用应用内的 liblzma 解压，兼容 PX4 preset-9 的 64 MiB 字典，并分别限制解压工作内存（128 MiB）和解压结果（16 MiB）；无需外部 `xz` 命令。当前工具不配置 MAVLink 签名密钥，签名帧会明确拒绝。

当前环境验证结果与未完成项见 [软件飞控测试记录](px4-sitl-test-20261122.md)。

```bash
node tests/px4-protocol.mjs
node tests/px4-messages.mjs
node tests/px4-simulation.mjs
node tests/px4-simulator-source.mjs
node --experimental-websocket tests/px4-sitl-ui.mjs
node --experimental-websocket tests/px4-toolbox-ui.mjs
node tests/flight-test-compiler.mjs
node tests/flight-test-native.mjs
node --experimental-websocket tests/flight-test-ui.mjs
cargo test --offline --manifest-path src-tauri/Cargo.toml --test flight_test
cargo test --offline --manifest-path src-tauri/Cargo.toml --test px4_sitl
# 允许本机 UDP 绑定时，额外运行端口占用用例
cargo test --offline --manifest-path src-tauri/Cargo.toml --test px4_sitl -- --ignored
cargo test --offline --manifest-path src-tauri/Cargo.toml --test px4_files --test serial_assistant
npx tsc --noEmit
npm run build
```

测试使用独立 MAVLink 线协议样例、本机 UDP/TCP/PTY 和浏览器原生键盘事件，不发送真实设备命令。主机验证不代替仿真机/飞控联调。
