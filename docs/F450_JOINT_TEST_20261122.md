## 定位恢复后，满推力但模型电机为零

本机 `13_54_24.ulg` 与同期 MCAP 的只读检查表明：

| 环节 | 观测 |
| --- | --- |
| PX4 HIL/解锁 | `hil_state=1`，`arming_state=2`，预检查通过 |
| PX4 定位 | 本地位置及速度有效，GPS 3D fix、10 颗卫星 |
| 控制分配 | `actuator_motors.control[0..3]` 约 `[1, 0.5642, 0.9951, 0.5672]` |
| 模拟输出功能 | `PWM_MAIN_FUNC1..4=0`；4005 机型把电机映射到 `SIM_GZ_EC_FUNC1..4` |
| HIL 输出锁定 | `actuator_armed.lockdown=true`，旧生成脚本使用 `pwm_out_sim start -m sim` |
| 模型输入/执行器 | `fcs/throttle-cmd-norm[0..3]` 与 `throttle-pos-norm[0..3]` 均为零 |

这说明 PX4 已计算出电机指令，但未通过正常模拟输出链路送达模型。MAVLink HIL 使用归一化
`HIL_ACTUATOR_CONTROLS`，并非直接传入微秒 PWM。

本次修复仅作用于 UDP HIL 生成脚本：

- 将模拟输出驱动改为 `pwm_out_sim start -m hil`，使用 PX4 为 HIL 设计的模拟输出模式。
- 对尚未配置的 PWM_MAIN 槽位继承对应 SIM_GZ_EC 电机功能，保留已有非零用户映射及所选机型几何。
- TCP/SIH 启动保持 `-m sim`。缺少唯一的输出驱动启动入口时明确失败。

增加可实际执行的 shell 回归用例，验证 Gazebo 电机映射迁移、用户映射保留和 commander/输出驱动的启动模式。
本次未修改正在运行的飞控或模型，修复后的端到端电机接收与悬停仍需在重启新进程后验证。

## 新输出模式生效后仍不动的续查

用户重启后的 `14_00_53.ulg` 仍显示 `PWM_MAIN_FUNC1..4=0`；生成的启动脚本已含
`commander start -h` 和 `pwm_out_sim start -m hil`，所以此次确认不是用户仍在使用旧脚本。
模型的新录制会话四路电机输入仍全部为零，PX4 控制分配仍接近满量程。

上一版映射迁移不完整：它通过 `param show -q SIM_GZ_EC_FUNC...` 读取功能，而本机不带 Gazebo
的原生 PX4 构建并不存在这些参数。该判断没有迁移任何电机功能。

现改为直接只读解析所选机型脚本中的常量电机功能，递归跟随 `${R}etc/...` 引用；
4005 的 4001 基础脚本明确提供 101、102、103、104。生成的脚本直接向空 PWM_MAIN 槽位写入这些
常量，不依赖运行时 Gazebo 参数，也保留已配置的用户输出映射。

已验证：缺少全部 Gazebo 参数的可执行 shell 回归通过；对本机实际 `build/px4_sitl_default`
的 4005/4001 脚本解析、四路映射生成和完整生成脚本的 `sh -n` 检查通过。启动器/本地仿真测试通过。
这些结果验证启动脚本生成，尚不代表修复后的端到端电机接收或悬停通过。

另做了一次完全隔离的模型升力检查：临时复制模型并移除网络输入/输出，在 1 秒时将四路
`fcs/throttle-cmd-norm` 设为 0.8，运行至 4 秒；模型海拔从约 285.06m 上升至 330.15m，无运行错误。
这证明模型会将有效电机输入转换为推力；它是离线开环检查，未控制正在运行的模型，不能计作 PX4 悬停验收。
