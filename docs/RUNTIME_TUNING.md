# 运行时调参

编辑器底部的“实时调参”默认开启。连接支持 `VPAR` 的新运行端后，运行或暂停模型时，可以修改下列已有参数：

- `pure_gain`、`scheduled_gain`、`aerosurface_scale` 的数值 `gain`；PID 的数值 `kp`、`ki`、`kd`。
- 已存在的 `clipto` 数值上下限。上下限成组发送，整个事务通过范围检查后应用。
- 常量块，以及 FCS / 气动函数表达式里的 `<value>` 数值，包括原来可在加载时折叠的常量表达式。
- 标准大气海平面压力、温度偏差、湿度、北/东/地向风、湍流类型、20 ft 风速和湍流强度。
- 风速、风向独立的固定值、正弦波、三角波和方波：在环境卡或“仿真配置 → 环境模型 → 环境风”编辑，点击“应用风场”整组应用。编辑和拖动预览时间轴不会直接改变运行端的风。
- 惯量节点的 `Ixx / Iyy / Izz / Ixy / Ixz / Iyz`：支持 `KG*M2` 和 `SLUG*FT2`，六项作为一个事务更新；省略的惯性积按 XML 默认值 0 处理。只换显示单位不会改变实际惯量。

惯量实时更新需要支持该能力的新运行端，旧固件会明确提示更新，不会显示“已应用”。只需为新增能力更新一次固件；之后运行或暂停中调惯量均不重载模型。修改的是 XML 中的基础机体惯量，燃油、集中质量及平行轴贡献继续叠加；运行端同步更新总惯量和逆矩阵，保留当前姿态、角速度、位置和仿真时钟。

非正定、接近奇异或超出数值范围的惯量矩阵整组拒绝，同一事务内其他参数也不会部分生效。运行端允许对角量不小于 `1e-12 slug·ft²`，矩阵分量绝对值不大于 `1e12 slug·ft²`，并进行归一化正定检查。惯性积的符号遵循所加载 XML 的 `negated_crossproduct_inertia` 设置。

输入框在 Enter 或失焦时提交，编辑过程中的空串、负号或指数前缀不会发送。底部提示只有在运行端完成应用并返回实际值、编辑器核对一致后才显示“已应用”。错误或通信超时会保留本地修改，不会自动重启模型。

如果先前的修改未发送或未确认，底部“重新应用”可再次提交当前数值修改，并等待回读确认；无需先改成另一个数值，也不会重载模型。

示波器为可拖动、可从右下角调整大小的浮窗，打开时仍可操作参数面板。

更新由拥有 FDM 的线程在仿真步之间执行，不调用 LoadModel、RunIC、Reset 或重新创建实例。暂停时也能应用，仿真时间保持暂停。示波器继续使用原来的实例、运行代次和历史记录。

## 保存

实时应用不会自动写 SD 卡。在工具栏选择“保存到仿真机”后，增益、限幅和常量进入原有 XML 比对、上传、回读流程。环境卡的数值合并到 `config/models/<model>.json` 的 `environment` 字段，与 XML 一起比对、保存、回读，其他配置分组保持原值。重新从任务机加载模型时会恢复环境卡。也可在“仿真配置 → 环境模型”修改和保存环境参数。

只保存工程会保存本机工程里的参数；要让任务机独立的下次启动使用新值，应完成“保存到仿真机”。

## 边界

仅能实时修改已经加载的数值参数。增删模块、改连线、改表达式结构、把数字改为属性引用、增加新的 clipto、修改查表结构仍需保存并重新加载。编辑器将当前结构与运行会话开始时的结构比较；结构改变后的常量不会套用到旧表达式的另一个位置。

每次事务最多 12 项，最多 32 个实例，实例、模型和运行会话必须匹配。旧运行端没有能力标识时只保留修改，不会把发送成功误报为应用成功。

波形风场需要上位机和运行端同时更新。运行端通过 `monitor.tuning.wind: 1` 声明能力，使用独立的 `VWIN` 报文整组提交 14 个字段，沿用实例、模型、运行会话、请求去重和实际值回读。原有 `VPAR` 的 12 项上限不变；风场不能拆成多个 `VPAR` 报文。旧固件会提示升级，不能把保存配置误报为实时应用成功。

## 周期环境风

风速为水平风速，单位 m/s；风向采用气象来风方向，0° 北风、90° 东风、180° 南风、270° 西风。两者分别设置基准值、振幅、周期、初相位，方波还可设置高值占空比。固定模式忽略振幅；正弦与三角波从基准值向高值变化，方波从高值开始（初相位为 0 时）。风向内部连续计算，最终方向读数归一到 `[0, 360)`。例如 350° ±30° 会经过北风，曲线连续显示 320°～380°。

风速基准值为 0～100 m/s，振幅为 0～100 m/s，周期风的振幅不能超过基准值；风向振幅为 0～180°。周期范围为 0.1～3600 仿真秒，运行端还要求非固定波形的周期至少包含 10 个积分步。初相位为 0～360°，占空比为 1～99%，垂直风为 ±100 m/s（向下为正）。整组校验失败时，运行中的参数均不变，界面保留草稿以便修正。

波形由每个实例的 JSBSim 风模型按仿真时间计算；暂停冻结，继续后接着变化，运行速度与墙钟无关。应用新配置从初相位重新开始，不重载飞机，不改变位置、姿态或仿真时钟；同一个请求的重传只重放 ACK，不会重新开始波形。关闭窗口或上位机断线不会终止已应用的风。固定三轴风仍可在高级设置使用；切回时先关闭周期风，再恢复三个固定分量。

周期风作为基础风，与现有阵风、余弦阵风和湍流相加。界面的“配置预览”只展示所配置的基础风，视景仪表和风袋继续读取 `atmosphere/total-wind-*-fps` 总环境风。两者在启用湍流等扰动时可以不同。

配置保存在 `config/models/<model>.json` 的 `environment.windProfile`，版本为 1，采用数字波形标识：0 固定、1 正弦、2 三角、3 方波。例如：

```json
{
  "environment": {
    "windProfile": {
      "version": 1,
      "active": 1,
      "speedWave": 1,
      "speedMeanMps": 5,
      "speedAmplitudeMps": 2,
      "speedPeriodSec": 10,
      "speedPhaseDeg": 0,
      "speedDutyPct": 50,
      "directionWave": 2,
      "directionMeanDeg": 90,
      "directionAmplitudeDeg": 30,
      "directionPeriodSec": 20,
      "directionPhaseDeg": 0,
      "directionDutyPct": 50,
      "downMps": 0
    }
  }
}
```

缺少 `windProfile` 或 `active: 0` 时继续使用原有固定北/东/地向风。加载配置时会将首个风样本写入初始条件，避免被 `RunIC` 覆盖。环境卡、本地工程和仿真配置保存共用此配置；保存到仿真机后，下次启动无需上位机持续发送风指令。

环境参数接受范围：海平面压力 `(0, 10000] PSF`，温度偏差 `[-150, 150] R`，相对湿度 `[0, 100]%`，三轴风 `[-1000, 1000] ft/s`，湍流类型整数 `0–4`，20 ft 风速 `[0,1000] ft/s`，湍流强度整数 `0–7`。运行端返回设定器实际接受的值；值被运行端截断时提示回读不一致。

## 验证入口

- `node tests/wind-profile.mjs`：波形数值、风向跨零、参数校验、整组映射、草稿与配置兼容。
- `node --experimental-websocket tests/wind-profile-ui.mjs`：真实配置窗口，隔离 IPC 验证草稿不发命令、整组应用、保存恢复、非法配置阻止保存、旧运行端能力检查和方波控件。
- 运行端 `python3 Tools/test_wind_profile.py --library build/native/src/libJSBSim.a`：真实 JSBSim 的风、暂停、请求去重、多实例、初始化、配置加载和旧配置兼容。
- `node tests/runtime-parameters.mjs`：参数标识、数值差异、限幅成组、环境单位换算、结构变化隔离，以及从 XML 导入的增益块首次将上限改为 `0.5` 的画布提交流程。
- `cargo test --manifest-path src-tauri/Cargo.toml --test runtime_tuning --test signal_monitor`：协议校验、真实应用 ACK、实际值不符、实例和模型检查、示波器队列。
- `node --experimental-websocket tests/runtime-tuning-ui.mjs <vite-url>`：浏览器中的草稿/提交、应用反馈、关闭调参、失败保留、模型检查和示波器历史连续性。IPC 为隔离模拟，不连接硬件。
- 运行端的 `Tools/test_runtime_tuning.cpp`、`Tools/test_runtime_tuning_udp.py`：真实 JSBSim 和 UDP，检查增益、限幅、常量、环境、状态保持、暂停、重试、会话隔离和保存后的新实例。
- `node --experimental-websocket tests/model-xml-sync-ui.mjs`：真实 Rust XML 解析/生成，检查导入组件的字符串限幅值保存为 XML 后重新导入仍保留，属性形式的限幅引用也不会被丢弃。
