# 连线实时数值与示波器

连线数值标签与示波器共享运行时采样，两者可以同时观察同一信号。
监视配置保存在工程的 `project.monitoring` 中，观察节点和观察支线单独保存在编辑器层。

## 使用

1. 双击数值信号线，显示或隐藏当前数值。标签可以拖动。
2. 原有添加拐点的操作使用 **Alt + 双击**。
3. 从部件库点击或拖入 **示波器 Scope**。新增部件放在当前可见区域，并避开已有部件。
4. 点击紧凑示波器的 `+`，再点击信号线；也可以从信号输出端口连到示波器输入端口。
5. 重复接线可以增加通道。示波器块显示当前数值，双击块或点击 `⤢` 打开波形窗口；`×` 删除示波器。
6. 时间窗口默认 **30 s**，可输入 **0.1～86400 s**，按 Enter 或离开输入框应用，并随示波器配置保存。也可滚轮缩放、设置纵轴和读取游标。
7. 窗口从仿真时间 0 开始，超过窗口长度后跟随最新数据。“回到起点”“历史”“较新”可浏览本次记录，“最新”返回实时查看。冻结显示期间继续在后台记录。

波形窗口可按通道选择原单位和显示单位，支持长度、速度、加速度、角度、角速度、力、质量、压力及温度。原单位可根据信号名称自动识别；未知时请手动指定。转换用于示波器数值、波形和游标，单位选择随工程保存，原始采样和连线标签保持原值。多通道共用纵轴时，刻度数值对应各通道各自选择的显示单位。

信号线上的青色圆点表示示波器接入位置，点击圆点即可打开对应波形。
接入点自动贴合信号线中心；移动模块或调整线形后会重新贴合，旧工程中的偏移接入点也会自动对齐。
如果已保存的示波器位于当前视野外，点击圆点还会将示波器部件移回可见区域。

关闭连线标签后，示波器仍可采集；删除示波器后，连线标签仍可显示。
主画布、系统/飞控/气动模块和公式编辑器都使用相同的观察层。
结构关联线展示相关运行量；没有数值绑定的关联线明确显示没有标量信号。

数值来自实际加载的运行模型。编辑模型以后，需要重新加载运行版本，才能观察修改后的行为。
内部运算结果在 JSBSim 正常求值过程中记录；观察端读取记录，不会为了显示波形再次执行随机函数或条件分支。
未采到的信号显示 `—`，暂停、停止、未执行分支和过期数据分别标明状态。

## 采样与范围

- 每个编辑器当前选择的实例最多同时订阅 **32 个不同信号**；同源标签和通道共享订阅。
- 每包最多携带 4 个监视信号，轮询所有已订阅项，控制数据包大小。
- 任务机“仿真配置 → 运行与时间 → 连线/示波器显示频率”控制发送频率，默认 **25 Hz**，范围 **1–100 Hz**。对应模型配置 `runtime.displayRateHz`，保存到任务机后重新加载模型生效。
- 单实例及多实例均使用此参数，普通属性遥测和订阅信号共享该发送节拍。实际频率受 FDM 步进、轮询数量和链路吞吐影响；暂停/停止时最多 10 Hz。窗口中的 Hz 根据收到样本的仿真时间戳计算。
- 参数文件位于 `/mnt/sdcard/jsbsim/config/models/<模型名>.json`；也可在 `config/global.json` 中设置全局默认，模型配置优先。例：`{"runtime":{"displayRateHz":50}}`。仿真步长和 MCAP 记录频率使用各自参数。
- Rust 接收端为每个实例缓存最多 256 个待消费包，包括旧运行端的属性树片段；前端逐批接收，避免界面的最新帧缓存漏掉属性或波形点。
- 已连接的通道从本次仿真开始在后台采集，关闭波形窗口不停止记录；暂停/继续保留记录，重新开始或加载新模型时清空对应实例的旧记录。
- 编辑器运行期间保留本次仿真的全部已接收样本，不再按 120 s / 12,000 点丢弃开头。原始数据按数值块保存，长时间范围绘图使用分级极值摘要，放大和游标仍读取原始样本。
- 要记录启动过程，应在仿真运行前接好通道。运行中新增通道只能从实际接入后的首次采样开始，编辑器不会补造此前的数据；波形记录不随工程文件写盘。
- 数据携带实例、模型运行代次、订阅版本和包序号。切换运行代次清空旧历史，旧订阅响应和乱序包被忽略，缺包处显示断点。

## 配套版本

带监视协议的运行端提供高频订阅和内部运算探针。旧运行端已有的属性树遥测也可以用于连线数值和示波器，采样频率受属性树轮询周期影响。
连线和示波器优先显示数值；悬停可查看“低速遥测”等来源说明及实际采样时间。过期、断线和未采到等异常状态继续直接显示。
属性是否过期按该信号自己的更新周期判断，不会因其他属性片段的大小变化而缩短有效时间；重复缓存包也不会刷新样本年龄。
编辑器保留实际采样时间，不会用重复缓存包补出高频波形。旧运行端的内部运算连线显示“内部信号需更新运行端”。
代码构建不会自动更新正在运行的桌面程序或板上固件。

Linux 本机运行时，构建使用本仓库配套的 JSBSim，设置 `SIM_EXTERNAL=0`，并在构建编辑器时设置 `JSBSIM_BIN` 和 `JSBSIM_ROOT`。
编辑器启动本机进程时启用回环接口 `JSBSIM_MONITOR_PORT=5803`，监视数据与本机遥测通过 5124 端口接收。
Windows 编辑器连接板端沿用 UDP/USB 协议；本机原生监视套接字适配目前面向 POSIX。

## 协议

订阅事务由若干不超过 160 字节的 `VMON` 包组成，UDP 和 USB 使用相同负载：

| 偏移 | 内容 |
|---|---|
| 0–3 | ASCII `VMON` |
| 4 | 实例编号 1–32 |
| 5 | 事务中信号总数 0–32 |
| 6 | 本包信号索引 |
| 7 | 保留 |
| 8–11 | 32 位小端订阅版本，不能为 0 |
| 12 起 | UTF-8 属性路径，最多 128 字节，无 NUL 终止符 |

总数为 0 是取消订阅。运行端收齐同一事务后才替换订阅；FDM 线程使用尝试加锁，通信线程更新订阅时不会阻塞 FDM 等待。

遥测增加 `monitor` 对象，包含 `version`、`revision`、`sequence` 和 `samples`。
每个样本是 `[value, simulation_time, is_constant, optional_operation_kind]`。
没有有效样本时 value/time 为 null。内部探针使用 `_monitor/value/n<16位十六进制ID>`，身份由函数所有者和运算节点位置生成，与画布坐标无关。
