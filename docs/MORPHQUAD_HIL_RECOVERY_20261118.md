## 主要触发因素：测试遥测请求增加 HIL 排队延迟

原始失稳时主杆和飞控姿态目标均为零，实际姿态仍放大；正常 RC 对照采用相同模型、主要控制参数和固件，松杆后能稳定。核对未发现足以解释差异的质量、惯量、步长、增益变化。

在同一持续运行的模型、飞控和固件上，将旧请求节奏恢复到对照二进制：

| 实测 | 修复后 `resume-02/short-01` | 旧查询对照 `resume-02/old-query-01` |
| --- | --- | --- |
| 飞行中 REQUEST_MESSAGE | 0.199 Hz，仅 5 秒一次身份查询 | 74.710 Hz |
| HIL_ACTUATOR_CONTROLS | 199.63 Hz | 192.63 Hz |
| 相对传输延迟 P99 | 32.48 ms | 138.32 ms |
| 结果 | 双轴 18 个点、19 次回位完成 | 0°阶段复现振荡，36.54 s 中止 |

延迟定义为“PCAP 到达时刻减飞控发送时刻”再减去本轮最小值；这是相对排队/抖动指标，**不是绝对 USB 单程延迟**。旧对照在倾角 17.2°、体轴角速度 121.5°/s 时触发边界；该对照没有发送非零激励。结论指向高频请求及其回复/ACK 对共享 HIL 链路的干扰，不据此宣称已证明 USB 原始带宽耗尽。

修复优先复用已有新鲜姿态、位置、速度和高度流，只为缺失流顺序配置并确认 ACK；身份查询每 5 秒一次，飞行中不高频轮询，也不在已解锁时退出重配流。

## 回位、短激励和退出修复

1. 大角度向回位模块交接时，从上一实际指令按倾角矢量变化率连续接管，避免先把 45°裁到回位限位造成首帧跳变。
2. 速度/位置比例控制存在固定残差。`full-01` 的 +20°后速度近零，却停在原点约 0.7 m 外；飞控估计姿态约有 0.8°偏差，与仿真物理姿态相对照符合恒定偏差的表现。新增有上限的低速速度积分补偿，近原点低速才学习，加速度向量上限 0.5 m/s²，大幅偏移/高速时冻结。
3. 普通 MANUAL 的到位后保持时长只由姿态和角速度稳定决定，油门控高继续运行。高度收敛由随后的回位共同验收，避免 +35°时等待高度稳定把两秒激励拖到 12 秒超时。普通手动激励仍有高度偏差边界 `min(目标高度/2, 3 m)`，倾角 60°和体轴角速度 120°/s 边界保持。
4. 退出自动模式前先以 50 Hz 连续回中 0.8 秒。`full-02` 中 LAND 已 ACK 成功，但 56 ms 后出现 `Pilot took over using sticks`，说明回中变化仍经过 PX4 的 0.1 秒变化率滤波，被当成飞手接管。新时序让滤波先收敛，不关闭接管保护或 RC 失联保护。
5. 降落期间维持中位输入和 GCS 心跳，等待新鲜着陆状态，再普通上锁或确认自动上锁。未使用强制上锁来完成正常降落。

回位验收始终为位置误差 ≤0.5 m、水平速度 ≤0.2 m/s，另有姿态/角速度、高度/爬升条件，连续满足 2 秒。单轴扫角期间每个角度之后回同一本轮原点，不每点重记原点。
